Create `src/onboarding/sitemap-fetcher.ts` for fetching and parsing sitemaps from brand domains.

Requirements:
1. Main export: `async function fetchAndParseSitemap(domain: string, productUrlPattern?: string | null): Promise<{urls: string[], sourceUrl: string}>`

2. Sitemap discovery protocol (full - option C):
   a. Try standard paths in order: `/sitemap.xml`, `/sitemap_index.xml`, `/sitemap-index.xml`, `/sitemap.php`
   b. If all standard paths fail (404/error), fetch `/robots.txt` and parse `Sitemap:` directives
   c. Also try Shopify-specific paths: `/sitemap_products_1.xml`

3. For each candidate sitemap URL:
   a. Fetch with `Accept: application/xml, text/xml, */*` header
   b. Check Content-Type and Content-Encoding headers
   c. If Content-Encoding is `gzip` or response body starts with gzip magic bytes, decompress with `Bun.gunzipSync()`
   d. Parse XML to detect if it's a sitemap index (`<sitemapindex>`) or a regular sitemap (`<urlset>`)
   e. If it's a sitemap index, recursively fetch and parse each child sitemap `<loc>`
   f. If it's a urlset, extract all `<url><loc>` entries
   g. If productUrlPattern is provided as a regex string, filter URLs that match the pattern

4. Use native Bun APIs:
   - `fetch()` with timeouts (15s per fetch)
   - `Bun.gunzipSync()` for decompression
   - DO NOT import xml2js or any XML parsing library — use simple regex parsing: match all `<loc>([^<]+)</loc>` patterns

5. Handle errors gracefully:
   - Network errors: log and try next path
   - Non-XML responses: log and skip
   - Empty sitemaps: return empty array
   - Max recursion depth for sitemap indexes: 3 levels

6. Cache interaction: This function should NOT handle caching directly. The caller (source-discovery.ts) will check cache first and only call this when cache is stale.
