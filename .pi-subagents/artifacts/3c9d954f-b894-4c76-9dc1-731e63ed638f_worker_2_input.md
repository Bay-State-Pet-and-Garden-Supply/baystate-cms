Create `src/onboarding/sitemap-matcher.ts` for matching onboarding items against sitemap URLs.

Context from our architecture decisions:
- Pre-filter approach: Domain URL pattern rules → token overlap → LLM picks best match
- Confidence scoring: base 0.7 for sitemap candidates, + up to 0.25 for token overlap
- The LLM uses the consolidated product name from Serper Pass 1 when available

Requirements:

1. Main export: `async function matchSitemapUrls(sitemapUrls: string[], itemName: string, consolidatedName: string | null, upc: string, domain: string, productUrlPattern?: string | null): Promise<SitemapMatchResult[]>`

2. Return type:
```typescript
interface SitemapMatchResult {
  url: string;
  confidence: number;
  sourceMethod: 'sitemap_name' | 'sitemap_upc';
  matchType: 'upc_exact' | 'llm_selected' | 'token_overlap';
}
```

3. Matching algorithm (three passes):
   a. **UPC exact match**: Check if any sitemap URL literally contains the UPC. If found, return as high-confidence (0.95) with matchType 'upc_exact'.
   
   b. **Product URL filtering**: If productUrlPattern is provided, filter sitemapUrls to only those matching the pattern. If no pattern, use generic heuristic: URLs containing /products/, /p/, /shop/, /item/, /dp/ in the path.
   
   c. **Token overlap pre-filter**:
      - Use consolidatedName if available, otherwise itemName
      - Tokenize the name (lowercase, split on non-word chars, filter words > 2 chars, remove common stop words)
      - For each product URL, extract slug (last path segment, strip extension)
      - Compute overlap: count name tokens that are substrings of URL slug (bidirectional matching like existing scoreResult)
      - Score = matches / totalTokens
      - Return top 10 candidates by overlap score
   
   d. **LLM selection**:
      - If 2+ candidates, call LLM via getLlmConfigForTask with the product_name_consolidation task
      - Prompt: "Given this product: [name], which URL is the correct product page? Return ONLY the URL."
      - LLM-selected URL gets +0.15 confidence boost
      - If no LLM, fall back to highest token overlap

4. For non-LLM matches, confidence = 0.7 + (0.25 * tokenOverlapRatio)

5. Handle empty productUrls gracefully — return empty array. Log diagnostics at each step.

6. Import getLlmConfigForTask and callLlmForTask from ./llm-client for LLM matching.
