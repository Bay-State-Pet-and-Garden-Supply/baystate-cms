## Staleness Patterns Found

### 1. Old Tab Names
- **`docs/plans/extraction-profile-overhaul-plan.md`** (lines 484, 487): References `Overview`, `Snapshot`, `Review` as the desired tab set. The actual code uses `Build`, `Review`, `Advanced`.
- **`src/client/components/ProfileBuilderWorkspace.tsx`** (file header comment line 2): JSDoc says "Provides a tabbed workspace (Overview, Snapshot, Review)" — also stale. (Not an .md file, but worth noting.)

### 2. Deprecated Component/Architecture References
- **`AGENTS.md`** (line 52): Lists `product-curator.ts` as the "Curator Orchestrator" — this is the old monolithic architecture that ADRs 0001-0006 and `classification-design.md` plan to replace.
- **`classification-design.md`** (line 72): Explicitly says to replace `product-curator.ts` — but it hasn't been replaced yet, making this doc aspirational rather than descriptive.

### 3. Outdated Architecture Descriptions
- **`AGENTS.md`** (lines 44-57): Describes a 5-stage pipeline in simplified terms that don't reflect the detailed domain model in `CONTEXT.md` or the classification system ADRs. For AI agents relying on this file, it provides an incomplete picture of the architecture.

### 4. Old AI Proposal Generation as Primary Method
- Not a significant issue. `docs/generated-profile-governance.md` and `classification-design.md` correctly describe AI proposals as "proposal-only" with human review required. No document presents AI generation as the primary/automatic method.
