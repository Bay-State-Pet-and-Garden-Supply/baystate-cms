## Acceptance Report

Implemented the requested change: an on-demand AI profile generation trigger wired to the Domain Diagnostics panel.

**What was added:**

1. **Server route** `POST /api/onboarding/settings/domain-diagnostics/:domain/generate-profile` in `src/server/routes/onboarding-routes.ts`:
   - Checks the `SHOPSITE_CMS_PROFILE_GENERATION_ENABLED` env flag (returns 400 if off)
   - Looks up the domain's cached sitemap via `listAllSitemapCaches()` (returns 400 if no cache)
   - Picks up to 3 sample URLs
   - For each URL: fetches HTML with `HTTP_EXTRACTION_HEADERS`, calls `generateExtractorProfile(url, html, expected)`, inserts any successful result into `profile_generations` as a `proposed` row
   - Best-effort: per-URL failures don't abort the batch; they are reported in the response
   - Returns `{ success, generationIds, sampledUrls, domain, failures }`

2. **Client API** `generateProfileForDomain(domain)` in `src/client/onboarding-api.ts` plus the `GenerateProfileResult` type.

3. **UI button** "🤖 Generate Profile" in each diagnostics row's Links column. Disabled (gray) when no cached sitemap exists; primary blue when one is available. Shows "Generating…" while in flight. After completion: alerts with proposal count + failures, scrolls to the Generated Profile Governance section, and refreshes the diagnostics table to update the generation count.

- Did not modify `page-extractor.ts`, `profile-generator.ts`, or any `profile-generation` repo
