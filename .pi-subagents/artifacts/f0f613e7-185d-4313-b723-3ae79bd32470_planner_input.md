# Task for planner

## Plan: Overhaul extraction profile proposal generation and review

Based on this oracle analysis, create a concrete implementation plan.

### Context

The proposal generator (`src/onboarding/profile-generator.ts`) currently works by:
1. Minimizing page HTML
2. Heuristically scanning for CSS selector candidates (title, image, etc.)
3. Sending candidates to an LLM which picks from the list
4. The result is a set of CSS selectors stored as a "generation"

The review UI (`ProfileProposalDrawer.tsx`, `ProfileGenerationReview.tsx`, `ProfileBuilderWorkspace.tsx`) shows a table of selectors with approve/reject per field.

### What's wrong (from oracle)

1. **LLM constrained to candidates** — can only pick from heuristic-discovered patterns. If the heuristic misses the image gallery selector (e.g., Dawn theme `.product__media-wrapper`), images fail and there's nothing the LLM can do.
2. **Review is selector-centric** — operator approves CSS selectors instead of extracted product data.
3. **Generate → validate → approve is disjointed** — three buttons, two tabs, no preview.
4. **Shopify productJSON ignored** — the richest data source on Shopify pages isn't used by the proposal generator.
5. **Price/brand ghosts** — fields removed from LLM prompt but still in review UI, `SELECTOR_FIELDS`, and approval flow.
6. **No variant strategy in review** — variant strategy exists in the generation JSON but isn't surfaced or reviewable.

### Oracle's recommended three-phase approach

**Phase A — Fix the proposal generator (backend, ~2 hours)**
1. Change LLM prompt: instead of "Choose from candidates", tell the LLM "Write the best CSS selector for each field. Candidates below are hints — you may write selectors not in this list." Keep candidate discovery as hints but don't constrain.
2. Add Shopify productJSON as a first-class extraction strategy (`shopifyJSONPath` field in the profile alongside CSS selectors).
3. Remove price/brand from `SELECTOR_FIELDS`, review tables, approval flow entirely.
4. After generating a proposal, immediately run the proposed selectors against the seed URL and store the extracted data as a `seedPreview` alongside the proposal.

**Phase B — Preview-driven review UI (~3 hours)**
5. Replace selector-approval table with extraction preview panel showing: extracted title, description, images (thumbnails), variant options (pills). "Looks correct" button → validates across samples → aggregate results → promote. "Something's wrong" button → feedback form → regenerates.
6. Merge Proposals and Validation tabs in ProfileBuilderWorkspace into a single Review flow: generate → preview → validate → approve.

**Phase C — Variant strategy in review (~1 hour)**
7. Surface variantSelectionStrategy in the review preview. Show detected options, container selector.
